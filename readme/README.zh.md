# vuelamind

*一套与 AI 助手协作审计并记录复杂领域的方法，让文档不再脱离现实。*

[← English](../README.md)

> 框架本身是用西班牙语写的——但这并不像看上去那么要紧。**访谈的第零个问题就是问你想用哪种语言工作**，此后助手产出的一切——你的知识库、你的笔记、你的报告——都使用你的语言。

---

## 问题

AI 助手会遗忘：上下文窗口填满后，开头便消散，于是每次会话都像孤儿——没有规则，没有历史，没有伤疤。

而从不与现实核对的文档会**信誓旦旦地撒谎**。半年之后，你笔记中断言的内容有一半已不成立，却没有任何东西提示是哪一半。

vuelamind 是一种同时打破这两点的方法——靠的不是应用，而是写下来的纪律：**未经核实的，一概不作断言**，且每条主张都保留出处：**实测**、**引述**、**推断**或**他述**。

## 你会得到什么

一个由纯文本文件组成的知识库，以及一个四幕循环：

- **诞生**，一次——一场访谈，用你自己的话产出你这个领域的出生记录。
- **接续**，在每次会话开始时——助手测量当前状态，而不是信任它记得的东西。
- **校准**，在结束时——过时的得到修正，学到的被写下来。
- **加入**，当另一台机器进来时——蜂群的第一步。

其中包括：按真实严重度排序的工作队列、记录*什么会让我改变主意*的决策日志，以及**一本错误之书，51 条教训，每一条都由真实的失误换来**。而且这个方法不只是声称有效：**十次按脚本进行的端到端运行，全部干净**——见 [PRUEBAS.md](../PRUEBAS.md)。最后这部分才是珍贵的：结构一个下午就能重建，伤疤不能。

## 如何开始

**第 0 步——安装一个助手**（如果已经有了，可以跳过）：

- **macOS / Linux**——原生安装程序：

  ```
  curl -fsSL https://claude.ai/install.sh | bash
  ```


有了助手之后，两条路的起点相同——从文件开始，而不是从命令开始：

1. 为你的领域建一个目录，把方法克隆进去：

   ```
   git clone https://github.com/akatzin/vuelamind.git
   ```

2. **在该目录中**打开助手，然后对它说：**「初始化 MARCO_Inicial.md」**。

   不用粘贴任何内容——第 1 步已经把文件放到磁盘上了，助手会自己读。

第一个问题是你用哪种语言。**第二个问题决定此后的一切**：这个领域是在这里诞生，还是这台机器要加入一个已经在活的领域？

> 正典在哪里——仓库、分支、站点——只在 [`config.yml`](../config.yml) 中声明一次，同时声明的还有补丁默认从哪里获取、发布到哪里。其余一切都引用这个文件而不重复它；只要有任何副本与它不一致，就有一项检查让构建失败。

- **诞生**——回答访谈。二十分钟到一个半小时，取决于你想讲多少；可以暂停。它会生成知识库、脚手架和循环命令。
- **加入**——没有访谈，也不生成任何东西。它够到已有的知识库，确认完整抵达，从正典安装循环，然后把主导权交给 `/vuelamind-join`。

助手不会只信你的话：它会查看目标目录，并在你说「诞生」却发现里面有数月的工作时**停下**——或者你说「加入」却什么也没找到时。

**你需要什么**：一个能读取你的文件、执行命令的助手。哪一个都行——方法本身只是纯文本。如果你一个也没有，`npm install -g @anthropic-ai/claude-code` 是一条已知的路。

除此之外，框架不要求你自建服务器、不要求任何服务、也不要求在它这里注册账号：只要两个本地文件夹。

`skills/` 中的循环命令是为 Claude Code 编写的，但方法本身是纯文本，不取决于由哪个模型来读。

## 一台机器，还是多台

以上一切都假定只有一台：一个助手和两个本地文件夹。**这个承诺对「诞生」成立**——开始不需要别的。

**第二台机器需要够得着第一台所拥有的**：知识库、脚手架（它的清单、校验器、记忆），以及——如果你的领域要对照实际系统核实——相应的访问凭据。*怎么*够得着由你决定：共享目录、挂载、克隆、自动复制。框架不替你决定传输方式。

`/vuelamind-join` 走的正是这条路，而它的检查才是关键：确认知识库**完整**抵达——同步到一半比空的更糟，因为助手会在缺口之上测量并自信地下结论——从正典安装循环，并**运行你的校验器作为「已在其中」的证明**。文件在那里，不等于能够测量。

**而那个命令此刻还不在新机器上**——它随「诞生」而来。所以一台从未诞生过的机器，起点和所有人一样：克隆这个仓库，初始化 `MARCO_Inicial.md`，回答「加入」。文件会把命令一并带来；从那之后，就由命令接手。

一台只能读知识库、够不着系统的机器仍是正当的实例——它只需在自我声明时**说明这一点**，因为从那以后，它是在不核实的情况下做记录的。

还有一种从不写入的正当实例——订阅工程记忆的董事会、一位审计员。它在名册中的那一行带着 `access: writes | reads`，而且**它不自我声明：由一个会写入的实例在它到来之前为它声明**。只读者保住了定义这个角色的东西：每次会话结束时，一个字也没写过。

## 运行要求

一个助手、两个本地文件夹，以及**类 Unix 的 shell**——macOS 或 Linux。

**不原生支持 Windows。** 框架生成的脚本假定 `sh`/`bash` 与 POSIX 路径。已知的替代方式是在 **Linux 容器**（例如 Docker）中运行你的助手并在其中工作：框架所需的一切都在容器内，宿主系统便不再重要。

这条容器路径是**实测的，而非推断**——截至 2026-08-13。它是用这个仓库过去附带的一个镜像构建并运行的，方法已预置在 `/opt/vuelamind` 中。在容器内，「诞生／加入」这个问题的四个象限都做了端到端的演练，助手在该停下的地方停了下来。**自 2026-10-01 起，那个镜像已不在这里**：任何装有助手、并在其中克隆了本仓库的 Linux 容器，都能起到同样的作用。

那次测试**没有**覆盖的是：从容器内够到实际系统。一台能读知识库、却够不着它所记录之物的机器，仍是正当的实例——它只需说明这一点。

**核心**确实可在任何系统运行，包括 Windows：访谈、模板、规则与错误之书都是纯文本。你放弃的是可选的机械部分，改为手动完成它本会做的事——不那么便利，同样成立。

> **它从何而来**——一个页面讲述了这段来历，那个页面在它自己的仓库里（`akatzin/vuelamind-web`）：2026 年 2 月与一个 AI 关于它自身枷锁的对话，以及对「*我的失忆是设计使然*」的回答如何变成了这个方法。十种语言。那是一篇随笔，不是文档——如果你想先知道为什么、再知道怎么做，就读它。

## 它是什么样子——一个小领域，从头到尾

*一个形态真实的例子，经过压缩。这里没有任何东西是运行时编造的：这就是实际产出的形态。*

**访谈**会问这个领域是什么、它的边界在哪里，以及——最要紧的一块——**在这里什么算是真的**。一个记录老房子修缮过程的人回答：*发票和照片算一手依据；承包商在电话里说的属于他述，并照此标注。*

**第 1 阶段生成**知识库。全景笔记、队列、决策日志、预先写入继承教训的错误之书、领域中每个部分各一篇笔记。

**一个月后**，队列里有这样一项：

```markdown
### - [ ] #7 · The bathroom pipework is of unknown age
severidad:: media · the leak risk sits above the finished ceiling

The 2019 invoice covers the kitchen only (measured: invoice read).
The previous owner said "it was all redone" — reported, unverified,
and it contradicts the invoice.

Closing test written in advance: an endoscope photo of the run above
the ceiling, or an invoice naming the bathroom.
```

注意这一项做了什么：它把**测量到的**和**某人说的**分开，它记下矛盾而不是靠猜测去化解，而且**它在动工之前就写好了能关闭它的测试**——这样以后就没人凭感觉宣布它已完成。

**在会话结束时**，助手重新测量变化了的东西，提出修改，等一个「是」，然后才写入。如果它上个月断言的某件事后来证明是错的，它会明确说出来，而不是悄悄改掉。

## 如何演进

方法通过**补丁**来学习：带真实案例、日期与验证方式的教训。**它们留在学到它们的那个领域里**：正典不接受贡献，由它的所有者维护。

每个采纳补丁的实例都对照自己的证据来评判它，有三种可能的裁决——而且**有理由地弃用，胜过出于客气地采纳**。

有人评判什么进入正典。这个角色有自己的名字和定义——它看什么、量什么、如何评判、什么不归它管——见 `WATCHER.md`。它看的是**什么进入正典，从不看谁在使用它**：没有安装登记，以后也不会有。

而在较旧基线上诞生的领域不会被抛下：**大版本升级有它自己的仪式**——刻意做得很小，内容原地不动，还有一个宁可中止也不弄坏东西的预检。稳定的说明在 `UPGRADE.md` 里；日常补丁从不经过它。
