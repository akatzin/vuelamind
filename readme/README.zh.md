# vuelamind

*一套与 AI 助手协作审计并记录复杂领域的方法，让文档不再脱离现实。*

[← English](../README.md)

## 问题

AI 助手会遗忘：上下文窗口填满后，开头便消散，于是每次会话都像孤儿——没有规则，没有历史，没有伤疤。

而从不与现实核对的文档会**信誓旦旦地撒谎**。半年之后，你笔记中断言的内容有一半已不成立，却没有任何东西提示是哪一半。

vuelamind 同时打破这两点——靠的不是应用，而是写下来的纪律：**未经核实的内容不写**，且每条主张都保留出处：**实测**、**推断**或**他述**。

## 你会得到什么

一个纯文本的知识库和三幕循环：**诞生**一次；每次开启会话时**接续**——测量当前状态，而非信任记忆；结束时**校准**。

其中包括：按真实严重度排序的工作队列、记录*什么会让我改变主意*的决策日志，以及**一本错误之书，41 条教训，每一条都由真实的失误换来**。最后这部分才是珍贵的：结构一个下午就能重建，伤疤不能。

## 如何开始

1. 将 `MARCO_Inicial.md` 完整粘贴进助手的新对话。
2. 说：**「初始化这个框架」**。
3. 回答访谈——约二十分钟，可以暂停。

无需服务器、工具或账号。一个助手和两个本地文件夹。

**第零个问题就是你想用哪种语言工作**，此后一切都以你的语言产出。

## 运行要求

一个助手、两个本地文件夹，以及**类 Unix 的 shell**——macOS 或 Linux。

**不原生支持 Windows。** 框架生成的脚本假定 `sh`/`bash` 与 POSIX 路径。已知的替代方式是在 **Linux 容器**（例如 Docker）中运行你的助手并在其中工作：框架所需的一切都在容器内，宿主系统便不再重要。

这条容器路径是**推断的，未经实测**：它应当可行，也没有迹象表明相反，但至今无人真正跑过。如果你跑通了，那值得提交一个补丁。

**核心**确实可在任何系统运行，包括 Windows：访谈、模板、规则与错误之书都是纯文本。你放弃的只是可选的机械部分，改为手动完成——不那么便利，同样成立。

## 如何演进

通过**补丁**：带真实案例、日期与验证方式的教训，以 pull request 提出。唯一的准入标准是通用性检验——*把你的教训中所有专有名词去掉重写一遍：它还成立吗？*——而且**有理由地弃用，胜过出于客气地采纳**。
